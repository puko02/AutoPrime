# ADR-005: Estratégia de Alta Disponibilidade

**Status:** Proposta (não implantada)  
**Data:** Entrega 2  
**Decisores:** Grupo AutoPrime  

## Contexto
No contexto de manter o AutoPrime no ar mesmo se uma VM ou uma zona inteira falhar, diante de a arquitetura atual depender de uma única VM numa única zona.

## Decisão
Decidimos por distribuir a aplicação em duas zonas (us-central1-a e us-central1-b), com o balanceador dividindo o tráfego entre duas VMs sem IP público, um único Cloud NAT para as duas zonas, o banco no Cloud SQL com uma réplica na outra zona e o bastion para o acesso administrativo.

## Alternativas Descartadas
Descartamos usar outra região (mais caro e complexo) e manter o banco dentro das VMs (cada VM teria dados diferentes).

## Consequências
Para alcançar que a aplicação continue funcionando se uma VM ou uma zona cair, com troca automática para a réplica do banco, aceitando que o custo mensal aumenta bastante, que o banco muda de MariaDB para MySQL (o Cloud SQL não oferece MariaDB) e que o bastion continua sendo uma máquina só.
